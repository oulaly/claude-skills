当用户要求「生成/初始化/重写/审查 CLAUDE.md」时执行。模板文件为本 skill 目录下的
[`CLAUDE.template.md`](CLAUDE.template.md)，先读取它再开始。

## 模式一：生成 / 重写

1. **收集事实**（禁止臆造）：
   - 读 `package.json` / `pyproject.toml` / `go.mod` 等，确认技术栈与脚本命令；
   - **所有写进文档的命令必须真实存在且可运行**（脚本名以配置文件为准，不凭记忆）；
   - 扫一遍目录结构，只写顶层与关键子目录，不罗列全部文件；
   - 已有文档（README、docs/）作为内容与链接来源。
2. **按模板填充**：占位符 `{{...}}` 逐项替换；模板中的 HTML 注释是填写指引，成稿中删除。
   某节无内容可写时**整节删除**，不留空标题。
3. **填充后自查**，对照下方「质量清单」逐条过。

## 模式二：审查现有 CLAUDE.md

对照「质量清单」逐项检查，输出问题列表（按 阻塞/严重/一般 分级），经确认后再动手修改。

## 质量清单

- **单一事实源**：每条信息只在一个地方详写，其他地方用链接；与本仓库其他文档
  （README、docs/）冲突的内容必须消除。
- **权威边界清晰**：多个文档管同一领域时，写明「以哪个为准」。
- **命令可执行**：所有命令与脚本名以配置文件为准；环境版本要求写明。
- **无机器相关信息**：不写本机绝对路径、内网 IP、个人账号；用占位符或相对路径。
- **常见陷阱**：记录该项目踩过的坑（症状 + 原因 + 对策），这是 CLAUDE.md 最有价值的部分。
- **长度克制**：全文建议 ≤ 300 行；细节放 docs/ 并用链接索引，CLAUDE.md 只做导航与规则。
- **流程规范**：若项目采用规范驱动流程（变更包/冻结点/角色分工），写明入口与强制规则，
  细节引用规范文档或 spec-driven-dev 系列 skill，不重复展开。
- **AI 协作协议**：明确 AI 可自主/须确认的操作边界与测试门禁（如团队已装
  ai-collab-guardrails skill，可简写为一行引用）。
- **中文撰写**（团队另有约定除外），术语表统一中英文叫法。
