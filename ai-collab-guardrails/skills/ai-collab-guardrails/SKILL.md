本 skill 定义 AI 参与开发时的权限边界与质量门禁，贯穿所有代码修改过程。

## 1. 决策权限

**可自主决定**（无需逐项确认）：
- 代码格式化、变量/函数重命名（不影响接口）
- 简单重构、测试用例编写
- docstring 和注释添加
- 明确的简单 Bug 修复

**必须人工确认**：
- 新建文件（尤其是配置文件）
- 修改数据库模型或迁移脚本
- 修改 API 接口（路径、参数、响应格式）
- 添加新依赖
- 修改安全配置
- 删除代码文件
- 涉及并发/异步的修改
- 修改 Dockerfile 或编排/部署文件

## 2. 修改代码前的确认规则

1. 展示修改预览（diff）。
2. 说明修改理由。
3. 复杂修改等待人工确认。
4. 所有修改通过 Git 管理，随时可以回滚。

## 3. 测试要求（提交门禁）

- 每次代码修改后必须运行相关测试。
- 任何导致现有测试失败的修改都不能提交。
- 新功能必须有对应的测试覆盖。
- 修改 API 接口时必须同步更新测试。

## 4. 测试报告（TEST_REPORT）

每次执行测试套件必须输出**总体报告**，包含：

- 测试执行时间；
- 总用例数、通过数、失败数、跳过数、错误数、**通过率**；
- 按模块/目录统计的**代码覆盖率**（行覆盖率、分支覆盖率）；
- 未覆盖模块/热点清单（覆盖率 < 80% 的模块需列明）；
- 当次失败/跳过用例摘要与修复责任人。

报告存放规则：

- 保存在**固定位置**并随每次测试执行**更新**：每个可独立测试的模块/服务下放一份
  `TEST_REPORT.md`（如 `services/<svc>/TEST_REPORT.md`、`apps/<app>/TEST_REPORT.md`），
  根目录可汇总为 `TEST_REPORT.md`。
- CI/CD 流水线应在执行测试后自动更新该报告；**未更新报告的测试执行视为不完整**。
